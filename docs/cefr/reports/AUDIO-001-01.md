## 3. Changes and rationale

| File | Change/purpose | Contract/WP criterion | Compatibility impact |
|---|---|---|---|

| `tests/unit/speech-plan.test.mjs` (new, 494 lines) | 24 test cases (30 subtest entries) with hand-written expected step arrays covering the full mandated matrix | TS-TEST-005; AUDIO-001 "Tests" row; owner test items 1–12 | None — new file; the unit-suite total grows 75 → 105 |
| `docs/cefr/evidence/AUDIO-001/01/**` + this report | Sanitized evidence and the delivery report | DR-001..008 | None |

Root cause / why this approach: the roadmap requires autoplay (repeat, examples, include-translation, start-at) to be correct, deterministic, and language-safe across A1/B2 (AC-11), but the existing autoplay logic lives inside controller code that mixes planning with browser speech, timers, and DOM highlighting (see `verbs-engine.js` autoplay queue and `tts.js` SpeechQueue). FP-DESIGN-010 already designates speech-sequence planning as a pure calculation. A standalone planner module (a) makes the language-safety and determinism rules testable at the unit level without a browser, (b) gives AUDIO-002 a stable seam to adapt the Verbs autoplay to, and (c) gives future UI highlighting a stable step identity. The design decisions (option validation throws; mixed emits two steps; skip + warning rather than substitution; out-of-range start returns empty + warning; zero items is a no-op) were chosen to make every behavior explicit and independently assertable. Scope deviations: none — the implementation matches the reported pre-edit plan, with one cosmetic adjustment during TDD (the exact wording of the `detail` field of warnings was settled during the RED→GREEN cycle; the structural fields were never changed). Tests or old assertions superseded: none.
