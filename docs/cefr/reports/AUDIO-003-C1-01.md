## 3. Changes and rationale

### 3.1 The single speakable-scope boundary (Finding 2)

- `js/core/app.js` — new `_getSpeakableWords()`: `getFilteredWords()` (the same engine rule that renders the table) filtered by `_isRowSpeakable()` (the historic hide-and-guess guard). This is the ONE ordered collection; `_populateStartWordSelect()` and `playAllWords()` both consume it, eliminating the second card list and the mutable numeric join.
- `_populateStartWordSelect()` — option values are the stable word ids (`value="${card.id}"`); the 1-based label is the card's position in the speakable scope; an empty scope renders zero options (no stale entries); the control selects the first card of the current scope after every rebuild.
- `playAllWords()` — the selected id resolves to its index via `resolveStartWordIndex(cards, value)` immediately before planning; the control is normalized to the resolved card (`startWordSelect.value = cards[startIdx].id`) so the option shown and the first utterance always reference the same card; the defensive `-1` branch (unreachable behind the empty-scope guard) stops the session.
- `js/core/cefr-audio.mjs` — new pure export `resolveStartWordIndex(cards, selectedId)`: exact-id index; non-string / empty / no-longer-in-scope id → 0 (first card — the documented deterministic fallback, which supersedes the former numeric out-of-range clamp rule); empty collection → -1; non-array input throws `InvalidCefrAudioInputError`; inputs never mutated. This is the only cefr-audio.mjs edit (a pure stable-scope helper, explicitly authorized by the assignment).
- `stopAudioQueue()` — the Start At reset moves into the stable-id space: the first card of the CURRENT speakable scope (or no value for an empty scope), replacing the numeric `'0'`.

**Scope calculation, before → after (A1 unit 1, 30 filtered cards, Hide Mixed alternating):** Start At options were built from the 30 filtered cards while playback planned from the 15 speakable cards — a 30-to-15 numeric join mismatch (the owner's `15. Bitte!` vs `sehr`). After the correction both build from the identical 15-card speakable collection (`['1-1','1-3',…,'1-29']`), the selected id `1-29` resolves to index 14, and the first utterance, highlighted row, progress identity, and control all reference card `1-29`.

### 3.2 Favorites-membership reconciliation (Finding 1)

- `toggleFavorite()` — snapshots the active filter's card-id membership BEFORE the change, re-computes it after the engine sets are updated, and on an actual change (only possible while the words `typeFilter === 'fav'` is active, since no other filter rule reads the favorite set): `stopAudioQueue()` (SpeechQueue mints a new generation — every stale onend/onerror of the cancelled session is invalid), `glossaryEngine.render()` (rerender from the updated favorite set), `_populateStartWordSelect()` (rebuild from the same current scope; empty scope → zero options). This holds from every authorized favorite path — glossary star, flashcard shared-card button, phrases-tab star — regardless of the active view (the hidden glossary DOM is rerendered so the scope is already correct when the user returns).
- No scope change (e.g. a favorite toggled under `all`/type filters, or a favorite of a card outside the current unit): the queue keeps playing untouched (the constraint guard), and only the star styling updates, exactly as before.
- `state.view === 'glossary'` star-styling path and the `fromPhrasesTab` phrases-panel reload are preserved for the no-scope-change path; the scope-change path renders star states from the engine set (no double styling).

### 3.3 Context-change rebuilds (design requirements 7 + 8)

- `hideTableColumn('de' | 'mixed')` — queue stop (pre-existing AUDIO-003 behavior) plus Start At rebuild AFTER the re-render, from the same collection playback uses; hiding English/Article leaves the speakable scope untouched and does not rebuild the control (selection preserved).
- `revealAllTable()` — compares the speakable membership before/after the reveal; on change: stop + rebuild (a reveal with nothing hidden changes neither queue nor control).
- `switchMode()` — the queue stop (pre-existing) plus Start At rebuild after `navService.switchMode()` (returning to the glossary re-renders the table; mixed-hide rows re-roll).
- `switchUnit()` / `setTypeFilter()` / initial boot — Start At rebuild after rendering (the unit/filter paths are pre-existing AUDIO-003 behavior, now reading the speakable boundary).

### 3.4 Preserved behavior (design requirement 9)

Language tagging, planner ordering (`planSpeechSequence` / `mapCefrSpeechStepsToQueueItems` with the same card collection), phrase/conversation playback, SRS, favorites persistence (including the shared-card favorite), and all pre-existing AUDIO-003 tests are unchanged in behavior. `tts.js`, `speech-plan.mjs`, level data, storage, contracts, CSS, and HTML were not edited. `glossary.js` needed no change.

One timing fix inside the RED suite's Hide Mixed test: `drive(page, 3)` finishes utterance 3 and the queue schedules the fourth speak through its 250 ms delay, so an explicit `waitForUtterance(page, 4)` was added before reading the transcript (the first run of the GREEN check exposed the race; the assertion itself — the exact three-card sequence — is unchanged).
