## 3. Changes and rationale

Production change — `js/core/verbs-engine.js` (46 lines added/adjusted, all in the controller lifecycle):

1. `loadDeck()`: `this.stopAudioQueue()` at the top, before any state mutation or rendering — a deck change redefines the active verb context, so the previous session is cancelled before the new deck is presented (owner repro 1).
2. `switchView()`: `if (v !== this.activeMode) this.stopAudioQueue()` before the view toggle — navigating away from the current view changes the visible autoplay context (the Play controls and table live in the glossary view while the floating player is a global element, so only cancellation can hide it).
3. Search input handler: `this.stopAudioQueue()` as the first statement — a search change (including a transition to an empty result set) redefines the visible verb context before the filtered context is rendered (owner repro 2).
4. `playAllVerbsAudio()` empty-controller-queue early return: now `{ this.stopAudioQueue(); return; }` — pressing Play with an empty queue stops whatever session still owns playback and restores the resting controls instead of leaving it alive (owner finding 2 / requirement "attempts to start playback when the controller queue is empty").
5. `playAllVerbsAudio()` empty-plan early return: same treatment — an empty planned sequence must not leave a previous session alive (requirement D).

Why `stopAudioQueue()` and no new mechanism: it already performs exactly the cancellation contract — `SpeechQueue.stop()` stops future utterances, clears the delayed-speak/watchdog/no-synthesis timers, calls `speechSynthesis.cancel()`, and mints a new generation so every outstanding callback of the stopped session is invalidated through the existing AUDIO-002 generation mechanism; it clears `.highlighted-speech` rows, hides the floating player, restores the Play/Pause controls (including a paused session's "Resume" label), resets Start-At, and can never fire a false completion (completion fires only from the natural-drain path, which generation guards make unreachable after stop). It touches nothing else, so the newly selected deck/search context loads intact. No redesign of the controls or planner; `js/core/tts.js`, `js/core/speech-plan.mjs`, `verbs.html`, and all stylesheets are byte-identical to the accepted base (verified in the scope diff).

Test changes — `tests/unit/verbs-audio.test.mjs` (+6 tests U1–U6, harness additions, A12 revision) and `tests/e2e/verbs-audio.spec.js` (+8 `[AUDIO-002-C1]` browser tests T1–T8):

- Unit harness (additive only): `queueLog.stopCalls` counter on the SpeechQueue stub; `documentStub.querySelector` (null) so the real highlight callback can run in the VM; `loadVerbsEngineModule(injectedSpeechQueue)` parameter so U6 can wire the real controller source to the REAL `tts.js` SpeechQueue; a synthetic two-deck dataset; `assertControlsResting()`.
- U1 deck-change cancel; U2 view-switch cancel; U3 empty-queue early-return stops a live owner; U4 empty-plan early-return stops a live owner; U5 paused-session cancel (not resume); U6 controller+real-queue integration — `loadDeck` stops the real queue, a stale utterance `onend` is a no-op after navigation, and a replacement session started in the new context is immune to the old session's late callbacks (strengthened in the supplement after the first probe round).
- A12 revision (CM-MOD-002/003, disclosed supersession): the original A12 asserted the empty-plan early return left the *harness-fake* controls untouched (`innerHTML === ''`), an artifact of the fake elements rather than real resting DOM. The owner correction requires the early return to stop any previous session and restore the resting control state, so the superseded assertions were replaced with the corrected resting-state contract (resting Play label, no `playing` class, Pause hidden with the resting label, floating player hidden, `stopCalls === 1`); the unchanged core of A12 (the empty plan never starts the queue) is still asserted, and the revised test is part of the RED set (it fails on the base).
- Browser tests T1–T8 (through the real controller and the deterministic speech mock, no arbitrary sleeps): T1 deck change while playing (owner repro 1) with stale `onend`/`onerror` no-op proofs and restart-exactness on the new deck; T2 paused session then deck change (controls restored, not resumed); T3 search-to-zero while playing with Play-as-clean-no-op (owner repro 2); T4 search to a different non-empty result set (13 known matches; only current verbs speak); T5 empty controller queue with a live owner; T6 empty planned sequence with a live owner; T7 view navigation away (floating player hidden, glossary intact on return); T8 stale callback from the replaced queue during a live new session (exact verb-only utterance fingerprint and per-row highlight immobility).
